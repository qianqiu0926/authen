# 小红书分享链接修复 · 2026-10-16

版本：20261016-xhs-share。地址：https://authen.classby.cn/authen/ 。

## 复现与原因

用户提交“皮肤好的人都要用很贵的精华吗 我现在25+之后护肤真的... https://xhslink.cn/o/6WU23kNz6Mv 来【小红书】一探究竟吧！”。旧版接口返回 422，提示没有正文或评价。

- 前后端只认 xhslink.com，缺少 xhslink.cn 的平台标签。
- 普通桌面读取请求经过短链接跳转后进入小红书登录页，读取器未说明登录原因。
- 小红书公开手机分享页能正常返回正文，但数据结构是 noteData.data.noteData / commentData，与原先的 note.noteDetailMap 不同，导致未提取。

## 修复

- 对真实小红书域名使用标准手机页面请求，仍经 DNS 地址校验和固定地址连接；逐次校验跳转、保留分享查询参数。未添加登录凭据、浏览器 Cookie、验证码处理或脚本执行。
- 同时解析旧电脑版数据、新手机页数据和 SETUP_SERVER_STATE 备用结构；支持 nickName、图片 url、公开评论及一层回复。
- 只接受对应笔记 ID；对同一评论 ID 去重，保留不同人说出的相同话术；不把评论总数当作已读评论。
- 安全解析数据中的 undefined，不修改正文字符串里的同名字面文字；仍不执行网页 JavaScript。
- 错误区分登录、验证、失效、读取失败；不把登录页或站点介绍当正文。代理返回 HTML 错误页时也给出清楚提示。
- 链接失败后自动回到输入页，保留文字、图片和音视频；可以打开原帖、补图或粘贴正文。补充后可跳过原链接继续分析，资料卡明确标注原帖未读到。换成新链接时恢复正常链接读取。

## 实测

- 用户原始整段分享文字自动识别为“小红书”。
- 本机和服务器读取到同一标题、作者 -uio77、正文、4 张配图地址；实际下载并分析前 3 张图，读到 19 条公开评论及回复，标明不是全部评论。
- 本机真实 DeepSeek 端到端返回种草笔记资料卡，能识别绿宝瓶精华体验中的泛红、细纹等说法；卡片显示正文已读、3 张图、19 条评价。
- 登录页测试明确返回 LOGIN_REQUIRED，恢复界面保留原输入和已上传的图片，支持只分析补充内容。
- 构建成功，46 项测试通过；包含手机/桌面/备用数据结构、ID 匹配、重复数据、评论数量、脚本不执行、真实分享格式、错误恢复及既有公开地址限制。
- 构建扫描未发现已配置的模型密钥。HTTP、HTTPS、authen、nginx、evopi-api 和原根站点保持正常。
