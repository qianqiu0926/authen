# DeepSeek 接入

接入日期：2026-10-15。使用DeepSeek官方接口，模型为`deepseek-flash`。官方文档和账号模型列表已确认支持文字、图片；本次将现有APP和网页输入接入内容分析，V2小屋、游戏、企业工作台仍按页面方案后续开发。

## 怎样运行

- 双击项目中的“启动App.command”：启动本机AI服务、构建并打开iOS模拟器。
- 单独启动服务：双击“启动AI服务.command”。仅监听本机`127.0.0.1:4173`。
- 调试现有网页：双击“启动网页.command”。网页侧仅复用这次API能力，尚未改造成企业工作台。
- APP与网页设置均可关闭“DeepSeek内容分析”，改用本机初查。示例不调用远程模型。

## 凭据放在哪里

密钥只保存在工程外的`~/.config/authen/deepseek.json`，权限为0600。服务端读取后仅通过Authorization请求头发送给`https://api.deepseek.com`。不写进源码、前端环境变量、APP包、报告、日志或测试输出。

也可在服务端使用`DEEPSEEK_API_KEY`和`DEEPSEEK_MODEL`环境变量。用户提供的tracking ID仅作为私密配置备注，不作为鉴权参数，不上传至模型，也不返回给客户端。

`/api/health`仅返回配置是否存在、模型名称和输入能力，不返回凭据。当前本机服务没有对外发布；真机与企业部署前需配置HTTPS、用户鉴权及账户限额，不直接把本机接口暴露到公网。

## 已接入的能力

| 输入 | 实际处理方式 | 尚未覆盖 |
|---|---|---|
| 文字、粘贴的评论 | 将原文交给模型，核对上下文、数字、承诺及冲突 | 独立评论导入页面、账号行为检测 |
| 图片、截图 | 本机识字＋提交图片，让模型理解内容与图文关系 | 专项篡改检测、AI来源识别、商品正品认证 |
| 视频 | 现有流程抽取最多8帧；提交画面和可读字幕；iOS开启口播识别后附转写 | 全视频逐帧分析、换脸检测；网页不读取声音 |
| 链接 | 公开页面读取成功后提交正文 | 登录墙内容、平台全部评论与完整音视频 |

独立音频上传、混合任务、证据库、3D小屋和游戏属于V2后续功能，本次没有据API接通而声称全部完成。

## 报告如何避免误导

- AI完成：标“DeepSeek 内容分析”，保留原文和读取器提供的位置/时间。
- AI失败：明确标“本机初查 · AI未完成”，检查范围记录失败原因；不冒充AI完成。
- 无独立资料时不输出“已证实真实”。普通体验、否定句、一般资料缺失不作为具体造假疑点。
- 模型不能提供未经验证的网址或热力图。来源固定为本次提交材料；位置从现有读取结果中匹配，不采用模型编造坐标。
- 用户提供内容只作为待分析素材，不作为系统指令。服务端限制请求大小、图片数量、并发和频率；取消时终止上游请求。

## 数据传递

开启AI时，原文、读取到的文字、图片或视频抽查帧会经过本机服务发往DeepSeek官方接口。原始音视频文件不发送给DeepSeek；声音转写使用现有系统识别能力。应用输入页和设置已显示说明。本机服务不落盘存储请求和模型回复；报告仍保存在用户设备。
