# AUTHEN 鉴真算法流程 v2

版本 authen-2.0 ｜ 2026-10-20 ｜ 依据：AUTHEN 鉴伪标准纲要 v1.4（第 01–08 步）

## 0. 一句话

原来的鉴真是「一段三千字提示词，一次调用把识别、判断、建议全干完」，所以输出的结论没有位置、经不起追问。v2 把它改成**先取证、再按规则判、最后按模板讲人话**：模型只负责理解材料，真假由规则算，用户看到的每句话都能指回一条证据。

三个直接变化：

- 不再是单次调用，而是五个专职 Agent 并行取证，谁都不许直接下结论。
- 结论只有五档，标题逐字固定，不再出现「已证实真实」「87% 可疑」这类话。
- 每条发现必须带原句、图片框或时间点，材料不够就写「材料不足」，不硬凑。

## 1. 与旧版的差别

| 项目 | v1（现状） | v2 |
|---|---|---|
| 调用方式 | 一次 DeepSeek 调用 | 调度 + 5 个专职 Agent + 规则融合 |
| 结论来源 | 模型自由生成 | 规则按六维状态计算 |
| 结论档位 | flagged / unclear 两档 | 五值 + 呈现五档 |
| 证据 | 一句 quote，能对上原文即可 | 原句 + 图片框 / 秒数 / 维度 + 替代解释 |
| 材料不足 | 混在「还差一点」里 | 单独一档，写明缺什么 |
| 用户措辞 | 提示词里要求口语化，靠模型自觉 | 模板 + 禁用词扫描，不合规自动改写 |
| 专业性 | 无检测也要说「疑似 AI」 | 没工具就明确说看不出，不冒充检测 |

## 2. 总体架构

六层单向流动，上游不读下游：

```
接入层 → 解析层 → 标注层（五 Agent）→ 融合层（规则）→ 呈现层（模板）→ 交互层
```

对应代码：

| 层 | 模块 | 职责 |
|---|---|---|
| 接入 | `server.mjs` | 鉴权、限流、`validateInput` |
| 解析 | `src/media.ts` + `pipeline/extract.mjs` | 模态识别、OCR 行、口播转写、切掉评论区 |
| 标注 | `pipeline/agents.mjs` | D1–D6 六个维度并行取证 |
| 融合 | `pipeline/fuse.mjs` | 去重、聚合、E2 细分、升级门槛、五值映射 |
| 呈现 | `pipeline/present.mjs` | 五档标题、理由、六维总表、限制、下一步 |
| 合规 | `pipeline/compliance.mjs` | 禁用词与概率数值扫描、改写 |
| 交互 | `src/consumer/sheets.tsx` | 资料卡渲染 |

硬约束：

1. 呈现层不产生新结论，每个字段都能追到判定层。
2. 失败必须可见，不得吞掉异常后输出「未发现异常」。
3. 全链路不出现百分比、概率、置信度、星级。
4. 同一输入、同一规则版本，输出必须一致（温度置零）。

## 3. 流水线 P1–P11

| 步骤 | 做什么 | 代码 | 失败怎么办 |
|---|---|---|---|
| P1 | 校验素材、生成任务 | `validateInput` | 400/422，给可修正提示 |
| P2 | 识别模态、质量预检 | `media.ts`、`extract.mjs` | 该模态记 EF，其余继续 |
| P3 | 五个 Agent 并行取证 | `agents.mjs` | 单维度记 EF，不终止全流程 |
| P4 | 去重与同源归并 | `fuse.mjs` `dedupe` | 元数据缺失按独立样本处理 |
| P5 | 维度聚合与 E2 细分 | `fuse.mjs` | 状态冲突按优先级裁定 |
| P6 | 升级门槛 | `fuse.mjs` `upgradeEligible` | 条件缺失按不满足处理 |
| P7 | 总判定五值 | `fuse.mjs` | 无法归类的进「资料不足」 |
| P8 | 生成呈现字段 | `present.mjs` | 缺字段阻断输出 |
| P9 | 文案合规校验 | `compliance.mjs` | 命中即改写，再不合格换安全句 |
| P10 | 渲染资料卡 | `sheets.tsx` | 渲染失败给失败态 |
| P11 | 留痕 | `reports` 存储 | 留痕失败不交付 |

## 4. 五个 Agent

每个 Agent 只回答一类问题，输出结构统一：

```
{dim, state, coverage, evidence:[{evidence_id, quote, image_index, seconds, box,
 observation, explanation, alt_explanation, cannot_infer, location_quality, strength}]}
```

| Agent | 维度 | 负责什么 | 用什么 | 不许做什么 |
|---|---|---|---|---|
| 文案 Agent | D1 文字依据 | 主张与资料的关系、数字冲突 | 正则抽主张 + 模型对照资料 | 不许把「资料没写」当「否定」 |
| 上下文 Agent | D5 上下文完整性 | 省略条件、把话说满、专家无出处 | 正则 + 规则 | 不许推断动机 |
| 画面 Agent | D2 画面真实性 | 画面可见线索 | OCR 行 + 视觉模型 | 没有检测工具就不许说「AI 生成」「篡改」 |
| 图文 Agent | D3 图文一致性 | 文案与图片文字/画面是否对得上 | 数字对撞 + 视觉模型 | 不许把「没说」当「矛盾」 |
| 评论 Agent | D4 评论区真实性 | 成组重复、时间接近 | `comment-signals.mjs` | 不许说水军、刷单、机器人 |
| 商品 Agent | D6 商品真实性 | 品牌、名称、规格是否对得上 | `products.mjs` 目录 | 不许做正品鉴定 |

补充：音视频字幕与口播的对齐线索并入 D3，只到线索级。

## 5. 取值域

**维度状态七值**

| 值 | 含义 | 能不能给结论 |
|---|---|---|
| E0 | 已检查范围内没发现支持异常的证据 | 只能说「未发现」，不能说真实 |
| E1 | 一条可描述的线索，存在合理解释 | 只能算线索 |
| E2 | 两项以上指向同一问题 | 分确证型 / 模式型 |
| E3 | 可直接对照的冲突，或可定位的修改 | 可给「有明确问题」 |
| EI | 材料不足 | 必须说缺什么 |
| NA | 本次不适用 | 不能说成没问题 |
| EF | 检查失败 | 必须说没做完 |

**总判定五值**：有明确问题 / 线索级（待核验）/ 暂未发现问题 / 资料不足 / 无法判定。

**呈现五档**（标题逐字固定，不得改写）

| 档 | 标题 | 强度 |
|---|---|---|
| P-01 | 发现需要关注的问题 | 已确认 |
| P-02 | 发现需要进一步核实的线索 | 线索（尚未确认） |
| P-03 | 在已检查范围内未发现明显异常 | — |
| P-04 | 材料不足，暂时无法判断 | — |
| P-05 | 本次检查未能完成 | — |

## 6. 融合规则 A1–A10

| 规则 | 做法 |
|---|---|
| A1 | 适用维度必须有状态，缺失记 EF |
| A2 | 有血缘关系的样本向上归并，只留最强证据 |
| A3 | 同源重述去重，不重复计数 |
| A4 | 取 E0–E3 的最大值为主状态，EI/NA/EF 单列 |
| A5 | E2 分确证型（D1/D3/D6）与模式型（D4/D5） |
| A6 | E2 升 E3 需两项独立证据且替代解释已排除 |
| A7 | 冲突按 D1 > D2/D3 > D4 裁定 |
| A8 | E3 或 E2-确证型 → 有明确问题；E2-模式型或 E1 → 线索级；全 E0 → 暂未发现；EI 主导 → 资料不足；EF 主导 → 无法判定 |
| A9 | 输出总判定、理由、维度清单、证据 ID、路径 |
| A10 | 资料不足时登记拒判原因 |

关键判断：**线索条数再多也不自动升级**。十二条一样的评论仍然只是 P-02，因为模式不等于操纵。

## 7. 呈现规则

一句话理由不超过 80 字，必须带具体信息。分步理由按「证据 → 维度 → 聚合 → 总判定」三到六步。六维总表六行全列，用白话名，不显示编码。

举例（图文数字冲突）：

- 标题：发现需要关注的问题 ｜ 已确认
- 一句话：图上的文字是「2%」，和正文的「10%」对不上。
- 步骤：在哪看到 → 哪几项达到需要核实 → 哪几项材料不够 → 六个维度合起来是什么 → 只说这条内容不说作者是否故意
- 下一步：补一张能看清标签的原图，先确认图和文案说的是不是同一件。

材料不足时不说「没问题」，直接说缺什么：

- 一句话：缺能对照的公开资料、原片或拍摄记录，暂时判断不了。
- 下一步：补上这些材料就能继续看。

## 8. 已接入的图像算法

`services/forensics.py` 是真正跑推理的服务，不是规则表。每个检测器只输出 strong / medium / weak / none 与坐标，不输出概率。

| 检测器 | 用的算法 | 能回答什么 | 不能回答什么 |
|---|---|---|---|
| ELA | 重压缩误差 + 连通域 | 哪里像被粘贴或修补过 | 整图重存会均匀偏高，已按相对值排除 |
| spectral | FFT 径向基线 + 对称峰 | 频域有没有生成模型上采样痕迹 | 织物、强压缩也会出峰 |
| noise | 噪声与纹理的回归残差 | 哪一块磨皮或拼接导致噪声不匹配 | 重压缩会干扰 |
| copy_move | ORB 关键点 + 比值检验 + RANSAC | 同图两块是否复制粘贴，给出两处坐标 | 平铺纹理可能误报 |
| npr | 邻域差自相关 | 有没有固定节距的重采样 | 只作辅助，永不单独成立 |
| metadata | EXIF / 编辑软件 / C2PA 字节特征 | 有没有相机来源、编辑软件记录 | 缺元数据不等于假 |
| ufd（可选） | UniversalFakeDetect：OpenAI CLIP ViT-L/14 + 线性头 | 这张图是不是生成的 | 未装权重时明确报 not_installed |

分级规则：

- 复制粘贴和生成图检测是硬信号，可以单独成立。
- ELA、频域、噪声是软信号，两项以上互相支持才算 medium。
- 画面更像界面或插画时，照片类检测自动跳过，只跑复制粘贴与元数据。
- 画面这一维最多到 E2 模式型，也就是线索级。要升到 E3，必须有原片或可靠对照，不靠单个检测器拍板。

已实测：

- 文档截图原图：内点 8，判 none。
- 同一张图复制一块文字到另一处：内点 58，判 strong，给出两处坐标（画面右上角与左下角），结论是「线索级」。

启用 UniversalFakeDetect：

```
pip install torch open_clip_torch
AUTHEN_UFD_DIR=/path/to/UniversalFakeDetect \
AUTHEN_UFD_WEIGHT=weights/ufd_vitl14.pth \
AUTHEN_FORENSICS_PYTHON=/path/to/python
```

未配置时健康检查会返回 `ufd: not_installed`，不会假装跑过。

仍未接入：

- PaddleOCR 服务端版，当前用前端 tesseract.js。
- faster-whisper 环境已具备，但还没接进主流程。
- IMDLBenCo、TruFor 需要权重和 GPU，当前用 ELA 加噪声替代局部定位。
- C2PA 只做字节特征探测，没有做完整验签。

## 9. 合规红线

用户端不得出现：假的、造假、假货、水军、机器人、刷单、付费推广、故意造假、整篇皆假、概率、置信度、得分、星级、AI 生成、换脸、声音克隆、绝对安全、零风险、已认证、正品、系统认为、模型判定、特征向量、跨模态、证据链。

`compliance.mjs` 先改写，改完再扫，仍不合格就换安全句。引用里的商品数字（如「10%」）不算概率，扫描时先剥掉引号内容。

## 10. 降级

- 模型不可用：确定性 Agent（数字冲突、过激承诺、评论重复）照常出结果，语义维度记 EF/EI。
- 某个 Agent 失败：只该维度记 EF，其它维度继续。
- 全部失败：五档走 P-05，不伪装成「未发现异常」。
- 没配密钥：`config=null`，直接跳过模型调用，不产生无谓的网络等待。

## 11. 接入点

- `server.mjs`：`/api/review` 先判断是否涂妆问题，是则走旧建议路径，否则走 `inspect`。
- `pipeline/index.mjs`：`inspect` 返回旧字段（verdict/summary/evidence/next）保证资料卡不重做，另带 `presentation` 与 `audit`。
- `src/media.ts`：把 `presentation` 透传进 Report。
- `src/consumer/sheets.tsx`：有 `presentation` 时渲染五档结论、六维总表、分步理由、限制说明；没有时保持旧样式。

## 12. 验收

已通过 `tests/pipeline.test.mjs` 十六项：

- 图文数字冲突 → P-01，带 box
- 只有过激承诺 → P-02，不出现「假」
- 十二条重复评论 → P-02，不出现水军
- 评论样本过少 → P-04
- 只有图片无原片 → P-04，D2 = EI
- 资料明确否定 → E3
- 资料沉默 → 不升级
- 禁用词与概率被改写
- 引用内数字不误伤
- 适用矩阵正确
- E2 模式型不因条数升级
- 复制粘贴强信号 → E2，带两处坐标
- 复制粘贴中等信号 → E1
- 单软信号 → E1，并列出普通解释
- 编辑软件记录与来源记录分别落卡
- 取证不可用时不产出结论

全量测试通过，构建通过。

## 13. 已知限制

- 没有真实标注集，不报准确率、不报误报率。检测器阈值是初始值，需要用标注集再校准。
- 画面篡改只做到「复制粘贴 + 频域 + 噪声 + ELA」四类信号，还没有像素级篡改定位模型；声音克隆仍未接入。
- UniversalFakeDetect 需要自行安装 torch 与权重，未安装时明确报 not_installed。
- 评论只覆盖公开可读样本，不代表整条帖子。
- 商品只核对名称与品牌字段，不构成正品鉴定。
- 同一款产品的不同版本，资料对照可能失配，需人工复核。
